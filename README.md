# E-commerce

## 📌 Описание
Проект находится в разработке. 

Цели:

- спроектировать нормализованную структуру БД для и написать SQL-запросы для работы с данными
- разработать рекомендательную систему товаров
- введение в production с помощью FastApi или Flask

## Данные

[Датасет с Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce/code),
бразильский E-commerce Olist, 
содержит информацию о 100 000 заказов, включая данные 
о клиентах, товарах, продавцах, отзывах и платежах и 
состоит из ключевых таблиц:
*   `olist_customers_dataset.csv`
*   `olist_orders_dataset.csv`
*   `olist_products_dataset.csv`
*   `olist_order_items_dataset.csv`
*   `olist_order_payments_dataset.csv`
*   `olist_order_reviews_dataset.csv`
*   `olist_sellers_dataset.csv`
*   `olist_geolocation_dataset.csv`:

Работа была направлена на приведение данных к виду, пригодному для построения признаков. Весь процесс можно разбить на несколько логических шагов, отраженных в SQL-скриптах репозитория:

### 1. Анализ структуры и первичная нормализация
*   Проведен анализ связей между таблицами
*   Установлены первичные ключи для всех справочников (клиенты, товары, продавцы и т.д.)
*   Созданы внешние ключи для обеспечения целостности данных и явного определения связей между таблицами

### 2. Очистка данных
*   Обнаружено, что почтовые индексы из таблиц клиентов и 
    продавцов не всегда присутствуют в справочнике геолокации. Для
    этого была создана отдельная нормализованная таблица zip_code,
    в которую собраны все уникальные почтовые индексы из всех
    источников (клиенты, продавцы, геолокация). Это устранило 
    избыточность и позволило корректно связать данные.
*   В исходных CSV многие колонки с датами и числами были в 
    текстовом формате. Для это были написаны скрипты для 
    принудительного приведения типов данных
*   Пустые строки в ключевых полях заменены на NULL для корректной работы SQL

### 3. Формирование витрины данных для ML
*   Создано представление (view) orders_master. Это таблица объединяет данные из 8+ исходных таблиц в один плоский денормализованный срез
